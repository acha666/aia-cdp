## 2. 对 plan.md 的评估

### 2.1 对照线上成立的部分

- 决策 7（下载 URL 不变）是硬约束而不是便利：三类 URL 已写进签发出的证书里。plan 的路径表满足。
- §6 的扩展识别列表与线上 AD CS CRL 的扩展集合完全一致（AKI、CA Version、CRL Number、
  Next CRL Publish、Freshest CRL、CRL Self CDP、Delta CRL Indicator），没有其他关键扩展，
  `scoped_crl_unsupported` 与 `unknown_critical_extension` 都不会误伤现有 CA。
- 时钟策略：AD CS 把 `thisUpdate` 回拨约 10 分钟（ClockSkewMinutes 默认值），线上数据
  `thisUpdate 12:39:48`、上传 `12:50:23`，不会触发"超前 5 分钟拒绝"。
- 规模：资源数以十计、历史 462 个对象约 400 KB。`catalog.json` + 目录列表足够；不要分页、
  数据库的非目标正确。
- 缓存：`max-age` 夹在 [60 s, 3600 s] 直接修掉线上 42 万秒的 CRL 缓存；证书 immutable 一年与线上一致。
- 运行时：wrangler 自动置备 R2、`run_worker_first`、`assets` 绑定与现有配置连续。

### 2.2 需要补充或修订的点（已写入 plan.md）

1. `Content-Disposition`：线上带 `attachment; filename=`，plan §6 没提。保留它——浏览器从 UI
   点击下载得到正确文件名，CryptoAPI 不受影响。
2. 明文 HTTP：AIA/CDP 客户端只走 `http://`。Cloudflare 侧不能对 `/ca/*`、`/crl/*`、`/dcrl/*`
   开 "Always Use HTTPS"（线上目前正确）；Node 部署的反向代理同理不得强制跳转。写入
   `operations.md` 的检查清单（切片 6）。
3. 根 CA CRL 不经 AD CS 助手，是离线 OpenSSL 产物手工上传。`aia publish` 与 UI 上传都覆盖；
   但它半年才换一次，`nextUpdate` 过期后 plan 只"接受并记录"。建议 stats 增加
   `expiringSoon`（nextUpdate 在 7 天内）并在总览页提示。已作为 §8 总览统计条的一项。
4. 迁移 §13 第 4 步：旧归档键是 `crl/archive/<base>-<crlNumber>-<sha256>.crl`
   （`r2/crls.ts` 的 `archiveExistingCRL`），可枚举且自带 CRL 号。历史迁移可以是确定性的
   （按 CRL 号顺序解析 `thisUpdate` 后写 blob），不必写成"尽力而为"。
5. §5.6 的 5 秒 TTL 备忘：每次下载固定两次小对象读取。AD 域内客户端量级下无所谓，
   但 Workers 每个 isolate 常驻，建议切片 5 测量时默认打开。不改决策，留在测量项。
6. §10 第 8、11 行所列的解析缺陷已在旧实现完成（§4），plan 改为"切片 5a 迁入"；
   新增第 27、28 行记录本次补齐的覆盖面与 UI 的 `include` 缺陷。
7. §8 前端整段改写为 §3 方案；§12 切片 5 拆为 5a（API 与客户端）与 5b（UI）。

## 3. 前端方案

### 3.1 为什么不是"迁入旧 UI 改客户端"

- 旧 UI 是单页三段卡片 + 展开详情，没有 URL：无法分享"某个 CRL 的详情"，刷新即丢状态。
- `useCollectionLoader` / `useDetailCache` 手写了请求代保护、共享 pending、刷新失效——这正是
  TanStack Query 的职责；Pinia 只是在包装这两个 composable。
- `ExtensionView` 是一条 300 行的 `v-if` 链；主题、语言、剪贴板、相对时间各自手写；
  每个 `dt/dd` 重复一串 Tailwind 类名。上传反馈、吊销表格、折叠、tooltip 都是手写且没有
  键盘与 aria 保证。
- plan §8 要改客户端、store、上传文案、徽标时钟、下载来源——改动面已接近重写 UI 层。
  同样的工作量放到一个有组件库的基座上，长期收益更高。

### 3.2 候选对比（2026-10-18 `npm view` 查验）

| 库 | 版本（发布日） | 与现有 Tailwind 4 / class 暗色 | 组件归属 | 数据表格 | 备注 |
| --- | --- | --- | --- | --- | --- |
| shadcn-vue + reka-ui | 2.8.2（08-08）/ 2.11.0（10-05） | 原生；沿用现有类名与 `dark:` 策略 | 源码复制进仓库，可改 | 需配 `@tanstack/vue-table` | 依赖只多 reka-ui、cva、clsx、tailwind-merge、lucide |
| Nuxt UI 4（Vue 模式） | 4.12.0（10-15） | 原生（同为 Reka + Tailwind 4） | 库内 | 内置 Table | 依赖树大（@nuxt/kit、tiptap、motion-v、unhead…），文档以 Nuxt 为中心，独立 Vue 是二等路径 |
| Naive UI | 2.45.3（08-27） | CSS-in-JS，与 Tailwind 双轨 | 库内 | DataTable 含虚拟滚动 | TS 一流、暗色与 zh-CN 内置；视觉偏后台 |

推荐 **shadcn-vue（Reka UI）+ Tailwind 4**：保住现有 Tailwind 4 与 class 暗色投资；组件在仓库里，
符合 plan "每个职责只有一个实现"的原则；Reka 提供 Accordion / Tabs / Dialog / Tooltip /
Toast 的键盘与 aria；两条运行时都只是静态资源，无服务端耦合。
备选：若 owner 更想要"装上就全有"的库，选 Naive UI，并把 Tailwind 限制在布局层。

### 3.4 页面与组件清单

- 总览 `/`：统计条（证书数、目标数、已发布、即将过期）；证书表（CN、签发者、有效期、状态徽标、
  DER/PEM 下载）；CRL 目标表（标签、full/delta、CRL 号、thisUpdate / nextUpdate、状态、下载）；
  上传卡片（拖放 + PEM 粘贴；结果 toast 与行内 Alert）。
- 证书详情 `/certificates/:id`：Header（CN、状态、下载）；Tabs：概览（主题/签发者 DN 表、有效期、
  公钥与签名算法含参数、指纹）、扩展（Accordion）、原文（PEM + 复制）。
- CRL 目标详情 `/crls/:targetId`：Header；概览（签发者链接、CRL 号 / base、时间、状态）；
  吊销列表（表格：序列号、吊销时间、原因、失效起始、间接签发者）；扩展。
- 扩展渲染：每个解析结果映射为 render block（rows / tags / general names / distribution points /
  access / policies / subtrees），未识别或解码失败显示 ASN.1 结构 dump 与原始 hex。
  这套映射与 `GeneralNameList`、`DistributionPointList`、`Asn1Dump` 本次已在旧实现写好，可平移。
- 从旧实现迁移的纯逻辑：`utils/status.ts`、`utils/dates.ts`、`utils/format.ts`、`utils/x509.ts`、
  `useCrlUploadInput`。
